# Cloudflare Configuration Guide

This document explains the Cloudflare-specific configuration required for
the hybrid deployment.

## Overview

Cloudflare provides three services for EchoFlow:

| Service | Hostname | Purpose |
|---------|----------|---------|
| **Cloudflare Tunnel** | `api.echoflow.in` | Routes API traffic to the VPS |
| **R2 Custom Domain** | `media.echoflow.in` | Serves HLS playback directly from R2 |
| **Cloudflare Pages** | `app.echoflow.in` | Hosts the static React frontend |

## 1. R2 Bucket Setup

### Create the bucket

1. Go to **Cloudflare Dashboard** → **R2** → **Create bucket**
2. Name: `echoflow-media`
3. Bucket type: **Private** (we set per-prefix ACLs)

### Create an API token

1. Go to **R2** → **Manage R2 API Tokens** → **Create API token**
2. Name: `echoflow-vps`
3. Permissions: **Object Read & Write** (scoped to `echoflow-media` bucket)
4. Save the `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` — these go in
   `.env.vps.example` and `.env.laptop.example`

### Set bucket policy for HLS playback

> **⛔ DO NOT ADD A PUBLIC-READ POLICY ON `hls/`. This step is obsolete and
> actively defeats the playback gate.**
>
> This section predates HLS token protection and contradicts
> `02-vps-setup.md` step 4, which correctly says the bucket starts private and
> **not** to add a public-read policy for `hls/*`. The policy below was never
> removed from this file, so following it makes every transcript and segment
> world-readable to anyone who can guess or enumerate a clip UUID — while the
> Worker still demands a valid token, which now looks like a broken edge
> rather than a security hole.
>
> **The correct state is an entirely private bucket.** `media.echoflow.in`
> points at the `echoflow-hls-worker` Cloudflare Worker
> (`workers/hls-token-worker/`), which validates the playback token and then
> reads the object through an R2 binding. The Worker is the only way in.
>
> Verify: the bucket has **no** policy statements, and
> `GET https://media.echoflow.in/healthz` returns
> `200 {"status":"ok","backend":"r2"}`.

<details>
<summary>Historical: the policy this section used to prescribe (do not apply)</summary>

1. Go to the `echoflow-media` bucket → **Settings** → **Bucket policy**
2. Replace any default policy with:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadHLS",
      "Effect": "Allow",
      "Principal": "*",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::echoflow-media/hls/*"
    }
  ]
}
```

**Why not make the whole bucket public?** Original uploads (`uploads/`) contain
user-submitted audio that may have copyright restrictions. Only the processed
HLS segments (`hls/`) are safe to serve publicly, since they are derived
content (transcoded, shorter, and intended for streaming).

</details>

## 2. R2 Custom Domain

> **Status: DEPRECATED for HLS.** When HLS token protection ships
> (see `docs/EXPLAIN/storage/04-hls-token-protection.md`), `media.echoflow.in`
> will point to a **Cloudflare Worker** (not R2 directly) so that HMAC-signed
> cookies can be validated at the edge. R2 will remain private (no public-read
> policy on `hls/`).

### Add custom domain

1. Go to **R2** → **echoflow-media** → **Custom Domains** → **Add custom domain**
2. Domain: `media.echoflow.in`
3. Cloudflare will automatically:
   - Provision a TLS certificate (Universal SSL, free)
   - Create a CNAME record for `media.echoflow.in` → `<bucket-id>.r2.dev`

### Verify

```bash
# After a clip is processed and HLS is uploaded to R2:
curl -I https://media.echoflow.in/hls/{clip_id}/master.m3u8
# Should return 200 OK
```

**Important:** The `PUBLIC_MEDIA_ENDPOINT_URL` in `.env` must be set to:
```
PUBLIC_MEDIA_ENDPOINT_URL=https://media.echoflow.in
```

The media URLs are generated by `backend/app/media_urls.py:43-59` which
appends the `PUBLIC_MEDIA_ENDPOINT_URL` prefix to the stored `hls/` path.

## 3. Cloudflare Tunnel (API)

### Create tunnel

1. Go to **Cloudflare Dashboard** → **Tunnels** → **Create tunnel**
2. Name: `echoflow-vps`
3. Select **Run a private network tunnel**
4. Copy the credentials file to the VPS:

```bash
# On VPS
sudo mkdir -p /etc/cloudflared
sudo cp /path/to/downloaded/creds.json /etc/cloudflared/<tunnel-uuid>.json
```

### Configure tunnel

Create `/etc/cloudflared/config.yml` on the VPS:

```yaml
tunnel: <tunnel-uuid>
credentials-file: /etc/cloudflared/<tunnel-uuid>.json

ingress:
  - hostname: api.echoflow.in
    service: http://localhost:80
  - service: http_status:404
```

### Run tunnel

```bash
# Install cloudflared (user installs separately)
# On Ubuntu/Debian:
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb -o cloudflared.deb
sudo dpkg -i cloudflared.deb

# Run as a service
sudo cloudflared service install
sudo cloudflared --config /etc/cloudflared/config.yml run
```

### Add public hostname

1. Go to **Tunnels** → `echoflow-vps` → **Configure** → **Public hostnames**
2. Add:
   - **Domain:** `api.echoflow.in`
   - **Service:** `http://localhost:80`
   - **TLS:** Full (strict) — Cloudflare → VPS nginx → gunicorn

```
Browser → Cloudflare (api.echoflow.in, TLS 1.2/1.3, Bot Fight Mode)
  │
  ▼
Cloudflare Tunnel (cloudflared on VPS)
  │
  ▼
nginx (:443, self-signed localhost cert)
  │
  ▼
gunicorn (:8000, Django)
```

### Verify

```bash
curl -I https://api.echoflow.in/health/
# Should return 200 OK
```

## 4. Cloudflare Pages (Frontend)

### Connect repository

1. Go to **Cloudflare Dashboard** → **Pages** → **Create app**
2. Connect your GitHub repository
3. Branch: `main` (or your production branch)
4. Build settings:
   - **Framework preset:** Vite
   - **Build command:** `npm run build`
   - **Output directory:** `dist/`

### Environment variables

Set these in the Pages dashboard under **Settings** → **Environment variables**:

| Key | Value |
|-----|-------|
| `VITE_API_BASE_URL` | `https://api.echoflow.in` |
| `VITE_HLS_ENDPOINT_URL` | `https://media.echoflow.in` |

The frontend (`frontend/sample_frontend/src/api/client.ts`) reads
`VITE_API_BASE_URL` from the environment and uses it for all API requests.

### Verify

After deployment:
```
open https://app.echoflow.in/
```

## 5. Security Settings

1. **Bot Fight Mode:** Enable under **Security** → ** Bots** → **Bot Fight Mode**
2. **Always Use HTTPS:** Enable under **Rules** → **Redirects** → **Always Use HTTPS**
3. **HSTS:** Enable under **SSL/TLS** → **Edge Certificates** → **HTTP Strict Transport Security**
   - Max-age: 31536000 (1 year)
   - Include subdomains: Yes
   - Preload: Yes (optional but recommended)
4. **CORS Policy:** The `DJANGO_CORS_ALLOWED_ORIGINS` in `.env.vps.example`
   must match `https://app.echoflow.in` exactly.

## Cost Notes

All of these Cloudflare features are available on the free plan:
- R2: 10 GB storage + 10 GB egress/month free
- Tunnel: Unlimited
- Pages: 500 builds/month + 100,000 requests/day free
- Custom domains: Included
- Universal SSL: Included

At 50 users with short-form audio cliffs, you should stay well within
these free tiers.
